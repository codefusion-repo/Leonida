# S5.1 — native diagnostic build security

Related to #20 and completed #17. Scope is only the fresh x64 gta6rt.exe from the CMake Release and direct MSVC paths. No game inputs, GPU tools, external DLL contents, release artifacts or personal-host execution. Host execution HOLD.

Both paths explicitly request /GS, /guard:cf (compile and link), /DYNAMICBASE, /HIGHENTROPYVA, /NXCOMPAT and /FIXED:NO. The post-build Python standard-library reader checks PE32+ AMD64, entry point, bounded nonoverlapping file/virtual section ranges, no writable+executable sections, ASLR/DEP/CFG header bits, DIR64 base relocation metadata, CFG load config pointer slots and sorted executable function table entries. /GS is a compile-time setting; these checks do not establish complete stack-cookie coverage or process-wide W^X. Existing S3 process mitigation and memory-policy tests remain necessary.

The analyzer inventories actual direct DLL and named symbol imports, rejecting unreviewed DLLs, specified remote-process imports, ordinals, bound/delay imports and managed PE images. The allowlist is a reviewed baseline hypothesis for MSVC Release, not automatic trust: unexpected imports require source/toolchain review before changing policy. CRT internals may import loader functions; inventory is not evidence that these functions execute. No runtime resolution or dependency loading is performed. API-set resolution, delay/dynamic dependencies, transitive OS/CRT dependencies, versions, signatures and malware status are outside this inventory. CycloneDX 1.5 JSON contains the binary hash and direct DLL dependencies only; omitted dependency graph entries are unknown, not proof of no transitives. Schema validation and independent tool corroboration remain review requirements.

CI uses the existing windows job and builds, runs the static gate before the existing diagnostic tests, and retains only JSON. The wrapper regression still performs its original fresh build; it is not a third approved output. Compiler/toolchain metadata records CMake compiler version/generator/SDK or vcvars MSVC toolset/SDK; direct cl /Bv output is in logs. Runner image, workflow, candidate, run and attempt are recorded. Standard runner toolchains remain mutable. Review exact logs, artifact metadata and the report's SBOM digest; no independent recomputation of binary hash is possible from JSON alone. No binary upload or new signing in this phase. ZAC-01: no extra build job; retain approved evidence 30 days, failed diagnostics 7 days. Existing PR and push checks and synthetic diagnostic tests are preserved. No release or host approval. See docs/secure-development.md.

Reference: Microsoft PE format (https://learn.microsoft.com/en-us/windows/win32/debug/pe-format), Control Flow Guard (https://learn.microsoft.com/en-us/windows/win32/secbp/control-flow-guard), CycloneDX 1.5 (https://cyclonedx.org/specification/overview/).
