# Diagnostic memory policy (S3.3)

No executable image mappings are supported. The diagnostic loader allocates private PAGE_READWRITE pages, copies and relocates validated bytes, then seals the entire image PAGE_READONLY before publishing its borrowed Module. A protection error unwinds the local RAII candidate. PE executable-section flags do not grant native execute permissions. Unknown callable shim lookups return nullptr; the unused machine-code thunk generator and its RWX pool are removed. Callable shims remain excluded from diagnostic builds.

Windows tests inspect every mapped region with VirtualQuery, including a zero-filled section with executable PE flags, verify release after injected exceptions at five stages (40 iterations), including simulated protection failure and post-seal failure, and check the dormant registry without calling functions. The source policy test detects named execute permissions and removed thunk APIs in runtime C++ source; it is a narrow regression guard, not proof that all possible executable allocations or OS module loads are impossible. Normal process code and OS dependencies still use executable pages. Actual VirtualProtect API failure, process-wide mitigations, external dependencies, and any future trusted execution mode require separate validation. Host execution HOLD.
