# PE symbol metadata (S2.3)

Parse import, delay import and export metadata from the original validated file before mapping or resolving symbols. Snapshot names, ordinal keys, export RVAs and IAT write offsets. Limit descriptors to 4096, records to 65536 per category and cumulative string bytes to 16 MiB. Strings must terminate within copied section data and use printable non-space ASCII. DLL names are restricted to simple .dll basenames. Reject forwarded exports and legacy VA-based delay import descriptors. Data exports remain supported. No game compatibility established.

The mapper binds the validated snapshot without re-reading writable PE metadata. This is not a complete DLL trust policy: native dependency loading, module lifecycle, unresolved shims, W^X and aggregate resource usage remain follow-up work. Tests are data-only and never execute images. Host execution HOLD.

S2.3 review policy: complete lookup and IAT spans (including zero terminators) must fit one copied section each. Ordinary unbound IAT contents must match lookup entries; if directory 12 is declared, ordinary IATs must fit inside it. Delay IATs may contain initial VA pointers and are eagerly replaced. Bound imports, bound/unload delay tables and legacy delay modes are not supported. A delay module-handle slot must be aligned writable data, but runtime helper/unload semantics remain unimplemented. Export tables and strings are bounded; exact shared strings are permitted, structural metadata aliasing is rejected, as are exports targeting recorded metadata. Relocations may not touch recorded symbol metadata except active delay IAT slots which are overwritten at binding. These stricter policies may reject otherwise valid PE files; real game compatibility remains unverified. See https://learn.microsoft.com/en-us/windows/win32/debug/pe-format.
