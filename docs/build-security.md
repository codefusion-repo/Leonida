# S5.2 — Default Build & Privacy Hardening

Issue #22. Host execution HOLD. Correction 01 separates lexical planning from metadata inspection. `plan` accepts explicit absolute path strings for input, output and work, explicit stages and 1–4 requested jobs. It checks syntax and conservative lexical overlap (including repository spelling) without accessing the supplied paths, resolving links, discovering directories, opening content or launching tools. No automatic download, restore, cached executable reuse or build. Build.bat remains disabled.

Exit 0 means lexical description only, not a validated input or available destination. Exit 2 rejects arguments/syntax; exit 3 denies `inspect`, `prepare` and `build` for valid requests. `inspect` has no approved metadata backend and refuses before any target access, even for an apparently local path. Existence, type, freshness, locality, reparse points, directory identity and effective containment are unverified. A real symlink/junction can have valid lexical spelling; its inspection is still denied. Tests verify this distinction rather than claim link detection without access.

Windows syntax rejects UNC/device forms, ADS, reserved names, trailing dots/spaces and tilde aliases; all roles reject relative paths, traversal, ambiguous separators, controls and excessive lengths. Case-folded comparison is conservative, not a filesystem identity guarantee. Drive syntax does not prove a local device; mounts, aliases, network-backed storage and TOCTOU require separate OS-level validation. No caller flag, mock, environment value or lexical result can authorize inspection. Strict resolution belongs only to a future independently approved metadata backend and does not alone establish containment.

Structured output and fixed error codes omit private path strings. CLI argv may remain visible to OS process observers; do not pass private paths to public CI. Synthetic tests run CLI subprocesses, compare fixture snapshots, intercept selected APIs, exercise real links and Windows batch canaries, and verify Git ignore rules. These are bounded regression observations, not global write/network enforcement or sandbox certification.

The requested job limit is declarative only. Actual resource quotas, process supervision, network isolation, tool identity, local S4 dependency preparation, cache integrity and all executor stages remain HOLD. Existing S4 and S5.1 CI policy is unchanged. No proprietary data or native runtime execution authorized. Use only independently authored synthetic fixtures in reviewed disposable environments. ZAC-01: existing jobs only. Full S5 and G4/G5 remain pending.
